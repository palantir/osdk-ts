title: ActionForm
description: An OSDK-aware form for running ontology actions. Renders fields from an action definition, validates input client-side, and submits with the action's applyAction.
---

> **Beta** — exported from `@osdk/react-components/experimental`.

## Usage

ActionForm fetches its own action metadata. Wrap your app in `OsdkProvider` and import the package styles once (see [Prerequisites](./Prerequisites.md) for the `@layer` order), then pass an action definition — fields, client-side validation, and submission are wired up out of the box. The form title is hidden by default; pass `showFormTitle` to show it.

> **Note** — `@my/osdk` is a placeholder for **your generated SDK package** (e.g. `@your-app/sdk`). Replace it with the actual package name in your project.

```tsx
import { updateEmployee } from "@my/osdk";
import { ActionForm } from "@osdk/react-components/experimental";

function UpdateEmployeeForm() {
  return <ActionForm actionDefinition={updateEmployee} />;
}
```

## Style API

`ActionForm` is built on `BaseForm`, so form layout and field styling are driven entirely by `--osdk-form-*` and `--osdk-input-*` CSS variables — set them on the form's `className` (or any ancestor) to restyle without forking the component. The token groups are:

- **Layout** — `--osdk-form-fields-gap`, `--osdk-form-content-padding-inline`, and `--osdk-form-content-padding-block` for spacing between and around fields.
- **Header** — `--osdk-form-header-*` for the (optional) title bar's border, typography, and padding.
- **Footer** — `--osdk-form-footer-*` for the submit footer and its error indicator.
- **Labels** — `--osdk-form-label-*` and `--osdk-form-field-gap` for field labels.
- **Validation** — `--osdk-form-required-color`, `--osdk-form-error-color`, and `--osdk-form-error-font-size` for required markers and error messages.

`ActionForm` adds no outer padding by default; apply internal spacing via the `--osdk-form-content-padding-*` variables and use margin/border/background on a wrapper for card-style framing. Shared input styling comes from the `--osdk-input-*` tokens. See the [**Form**](./CSSVariables.md#form) and [**Input**](./CSSVariables.md#input) sections of [CSSVariables.md](./CSSVariables.md) for the full list of variables and their defaults.

## Advanced

`ActionForm` is the OSDK-aware component most consumers should use. For cases where you need to bring your own data or assemble a form from smaller pieces, the package also exports the OSDK-agnostic base component and the field-definition building blocks. All are available from `@osdk/react-components/experimental`.

### Base component

`BaseForm` is the OSDK-agnostic form that renders sections, fields, validation, and a submit footer from primitive props. It carries all of `ActionForm`'s layout and field rendering but does no action-metadata fetching — feed it a `formContent` array of `FormContentItem`s (standalone fields and sections) and an `onSubmit` handler. Like `ActionFormProps`, `BaseFormProps` is a controlled/uncontrolled discriminated union: provide both `formState` and `onFieldValueChange` for controlled mode, or omit both for uncontrolled mode.

### Building blocks

Field-definition types and per-field prop shapes exported so you can author `formFieldDefinitions` (for `ActionForm`) or `formContent` (for `BaseForm`) with full type-safety. The `fieldComponent` string narrows `fieldComponentProps` to the matching prop shape below.

| Export                    | Description                                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `FormFieldDefinition`     | OSDK-typed definition for one field of an action. `fieldComponent` narrows `fieldComponentProps` to the matching field prop type. |
| `RendererFieldDefinition` | OSDK-agnostic field definition consumed by `BaseForm`/`FormContentItem` — no generics or action-parameter constraints.            |
| `FormFieldPropsByType`    | Map from each `FieldComponent` type string to its props interface.                                                                |
| `FieldComponent`          | Union of the built-in field component type strings (`"TEXT_INPUT"`, `"NUMBER_INPUT"`, `"DROPDOWN"`, …).                           |
| `BaseFormFieldProps`      | Common props shared by every field component: `value`, `onChange`, `error`, `disabled`, `id`, `defaultValue`.                     |
| `TextInputFieldProps`     | Single-line text input props (`placeholder`, `minLength`, `maxLength`).                                                           |
| `TextAreaFieldProps`      | Multi-line text area props (`rows`, `wrap`, `minLength`, `maxLength`).                                                            |
| `NumberInputFieldProps`   | Numeric input props (`min`, `max`, `step`, `placeholder`).                                                                        |
| `DropdownFieldProps`      | Select/combobox props: `items`, `itemToStringLabel`, `renderItemLabel`, searchable and multi-select options, portal controls.     |
| `RadioButtonsFieldProps`  | Radio group props (`options`, `orientation`).                                                                                     |
| `FilePickerProps`         | File picker props (`isMulti`, `accept`, `maxSize`, button/empty text).                                                            |
| `ObjectSelectFieldProps`  | Object selector props — scope options by `objectType` or a pre-scoped `objectSet` (mutually exclusive).                           |
| `ObjectSetFieldProps`     | Read-only object-set summary props (`emptyMessage`).                                                                              |
| `CustomFieldProps`        | Props for a fully custom field, supplying a `customRenderer`.                                                                     |
| `UnsupportedFieldProps`   | Props for the disabled placeholder rendered for unsupported parameter types.                                                      |
| `Option`                  | `{ label, value }` pair used by radio and dropdown options.                                                                       |
| `ValidationError`         | Discriminated union describing which built-in validation rule failed and its constraint data, for custom error messages.          |
| `FormContentItem`         | One entry of `BaseForm`'s `formContent` — either a standalone `field` or a `section` grouping fields.                             |
| `FormSectionDefinition`   | Configuration for a form section: title, description, columns, collapse behavior, and visual style.                               |
| `FormState`               | Form values keyed by parameter name — the shape passed to/from controlled mode.                                                   |
| `FormError`               | Discriminated union surfaced to `onError` (`"validation"`, `"submission"`, `"unknown"`).                                          |

### Hooks

No headless hooks are exported yet; the form's state lives inside `BaseForm` (and `ActionForm`, which wraps it).
