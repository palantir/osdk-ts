---
title: FilterList
description: An OSDK-aware filter panel for ontology objects. Renders a list of filter controls — listogram, select, range, keyword search, and more — driven by aggregations against an object type or ObjectSet, and emits a composed where clause or filtered ObjectSet.
---

> **Beta** — exported from `@osdk/react-components/experimental/filter-list`.

## Usage

FilterList fetches its own facet data. Wrap your app in `OsdkProvider` and import the package styles once (see [Prerequisites](./Prerequisites.md) for the `@layer` order), then pass an object type and a set of filter definitions — aggregation counts, dropdowns, add/remove, and reset are wired up out of the box.

> **Note** — `@my/osdk` is a placeholder for **your generated SDK package** (e.g. `@your-app/sdk`). Replace it with the actual package name in your project.

```tsx
import { Employee } from "@my/osdk";
import { FilterList } from "@osdk/react-components/experimental/filter-list";

function EmployeeFilters() {
  return (
    <FilterList
      objectType={Employee}
      filterDefinitions={[
        { type: "PROPERTY", key: "department", filterComponent: "LISTOGRAM" },
        { type: "PROPERTY", key: "jobTitle", filterComponent: "LISTOGRAM" },
      ]}
    />
  );
}
```

## Advanced

`FilterList` is the OSDK-aware component most consumers should use. For cases where you need to bring your own data fetching or assemble the panel from smaller pieces, the package also exports the OSDK-agnostic base component, the individual building blocks, and the headless hook that backs them. All are available from `@osdk/react-components/experimental/filter-list`.

### BaseFilterList

`BaseFilterList` is the OSDK-agnostic panel that renders the filter list chrome — header, reset, active-filter count, add/remove, drag-to-reorder, and collapse — from primitive props. It carries all of `FilterList`'s layout and interactions but does no data fetching or where-clause composition: you supply the filter states map, a `renderInput` callback for each filter's body, and `getFilterKey` / `getFilterLabel` accessors.

### Building blocks

Standalone sub-components used internally by `FilterList`, exported so you can compose them into a custom filter UI.

| Export          | Description                                                                                                                                                    |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FilterPopover` | Labeled, popover-backed filter trigger that shows a short summary of the current value and mounts its popup contents only while open. Pair with `FilterInput`. |
| `FilterInput`   | OSDK-aware input body for a single filter definition. Renders the right control for the definition's `filterComponent` and drives its filter state.            |

The package also exports a set of utilities for building your own filter UI: `serializeFilterStates` / `deserializeFilterStates` (persist a filter-states map to and from a string, preserving `Date` values), `filterHasActiveState` (whether a state holds an active value), `NO_VALUE` (the sentinel for the null/undefined "No value" bucket), `getFilterKey` / `getFilterLabel` (derive a stable key or display label from a definition), `summarizeFilterValue` (a short summary of a filter's current value for a `FilterPopover` trigger), and `narrowObjectSet` (apply linked-property filters to an `ObjectSet<Q>`).

### Hooks

Headless hook holding the panel's state and where-clause logic. Reach for it when you're building your own filter UI from the building blocks above rather than composing `BaseFilterList`, and want to reuse FilterList's state management and OSDK query composition.

| Export               | Description                                                                                                                                                                                                                                                     |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useFilterListState` | Owns the filter-states map — seeded from the definitions and `defaultFilterStates` — and composes it into a direct `WhereClause<Q>`, the active linked-property records to apply via `narrowObjectSet`, and per-filter excluding-self clauses for facet counts. |
