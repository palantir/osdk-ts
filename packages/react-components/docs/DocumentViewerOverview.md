> **Beta** — exported from `@osdk/react-components/experimental/document-viewer`.

## Usage

DocumentViewer takes an OSDK `Media` object, detects its MIME type, and renders it with the matching viewer. There is no data-source wiring to configure — pass the `Media` value from an object property and the component handles the rest.

> **Note** — `@my/osdk` is a placeholder for **your generated SDK package** (e.g. `@your-app/sdk`). Replace it with the actual package name in your project.

```tsx
import { DocumentViewer } from "@osdk/react-components/experimental/document-viewer";

function TrainingMaterial({ employee }) {
  return <DocumentViewer media={employee.trainingMaterial} />;
}
```

Each format's viewer accepts its own options via a pass-through prop (`pdfViewerProps`, `imageViewerProps`, and so on). Only the prop matching the resolved viewer is applied.

```tsx
<DocumentViewer
  media={myMedia}
  pdfViewerProps={{ initialSidebarOpen: true, enableDownload: true }}
  imageViewerProps={{ alt: "Product photo" }}
/>
```

When the MIME type is missing or ambiguous, hint the format with `mimeTypeOverride` or `fileName`.

```tsx
<DocumentViewer media={myMedia} mimeTypeOverride="application/pdf" />
```

## Style API

DocumentViewer exposes its appearance through `--osdk-*` CSS variables, so you can theme it by overriding tokens without forking the component. The root container reads two tokens:

| Variable                        | Purpose           |
| ------------------------------- | ----------------- |
| `--osdk-document-viewer-bg`     | Viewer background |
| `--osdk-document-viewer-border` | Viewer border     |

Each per-format viewer carries its own token group — `--osdk-pdf-viewer-*`, `--osdk-image-viewer-*`, `--osdk-video-viewer-*`, `--osdk-markdown-renderer-*`, `--osdk-excel-viewer-*`, `--osdk-email-viewer-*`, and `--osdk-xml-viewer-*`. See the [CSS Variables reference](https://github.com/palantir/osdk-ts/blob/main/packages/react-components/docs/CSSVariables.md) — in particular the **Document Viewer**, **PDF Viewer**, and **Markdown Renderer** sections — for the full list of tokens and their defaults.

## Advanced

`DocumentViewer` is the single entry point most consumers need. It dispatches by MIME type to a per-format viewer (PDF, TIFF, image, video, markdown, Excel, email, XML) and falls back to a message for unsupported types such as `.doc`/`.docx`. There is no separate base component, building blocks, or headless hooks to compose — the individual viewers are not exported from `@osdk/react-components/experimental/document-viewer`.

Instead, customize the selected viewer through the pass-through props documented in the [Props](#props) table above: `pdfViewerProps`, `imageViewerProps`, `videoViewerProps`, `tiffRendererProps`, `markdownRendererProps`, `excelViewerProps`, `emailViewerProps`, and `xmlViewerProps`. Each forwards its object (minus the `src`/`content`/`className` props DocumentViewer manages itself) to the matching viewer.

The package also exports the `ViewerType` enum, which enumerates the viewer DocumentViewer can resolve to (`Pdf`, `Tiff`, `Image`, `Video`, `Markdown`, `Excel`, `Email`, `Xml`, `Unsupported`) — useful for identifying or asserting which viewer a given MIME type maps to.
